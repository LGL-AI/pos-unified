# Customer display

`DisplayManager.DISPLAY_CATEGORY_PRESENTATION` chooses a non-primary presentation display; no display ID is hard-coded. Android `Presentation` hosts the RC5 `/display/` UI bundled in the APK. The app creates a D1 pairing once a secondary display is attached and the staff is signed in. The counter sends server-calculated cart snapshots while selecting items, and order snapshots after order creation/payment. The customer page polls the configured HTTPS server with its separate pairing token every 3 seconds. Unplugging/reconnecting the display recreates the Presentation.

Expected states: welcome, cart, bank QR or cash payment, and paid confirmation. While the counter has an order open, changes from handheld POS or QR are fetched from D1 every 10 seconds and refresh the paired snapshot when its order version, payment, refund or bill state changes; the customer page reads that snapshot every 3 seconds. The app creates a new pairing shortly before the 12-hour expiry and reloads the second screen. Pair tokens are never placed in the APK source. The Windows test EXE can turn on Android's virtual overlay display and save a screenshot/log. A physical second screen and its display mode still need a device test.

Android Studio Emulator (Android 11 API 30): open **Extended Controls (⋮) → Displays → Add secondary display → Display 1 → 720p (1280 × 720) → Apply Changes**. Return to the emulator, open the customer display window, sign in to the POS, then go to **Tùy chỉnh cửa hàng → Màn hình thứ hai** to verify that the app sees the second display. If a prior 401 or expired pairing is shown, use **Kiểm tra và ghép lại màn hình**. The button resets the old display session, pairs again against D1, and updates the customer `Presentation` without restarting the app. Signing out clears the customer screen. A second display added after login is detected through `DisplayListener` and pairs automatically. A session token change bypasses an earlier 30-second pairing cooldown.
